# 内容是构建产物，不是运行时数据

上游 HowToLiveBetter 仓库活跃更新（350+ commits），但我们把 672 条内容在**构建时**解析打包进 App（只读 `entries.json`，记录解析时的 commit sha），不做运行时拉取或在线检查更新。理由：本 App 的核心承诺是完全离线零网络依赖，内容是长期有效的建议而非时效信息；运行时同步要付出拉取、缓存失效、离线合并三套逻辑的代价，换来的新鲜度对自用场景无感。用户状态（决策/打卡/收藏）存 IndexedDB，与内容以条目 id 关联——上游删除条目时用户行成孤儿，UI 隐藏、数据保留。更新内容的唯一方式是重新构建部署，用户数据不受影响。

## Consequences

- 手机上内容永远滞后于上游，直到下一次手动构建。
- 换运行时同步方案属于架构级返工，见本 ADR 再决策。
